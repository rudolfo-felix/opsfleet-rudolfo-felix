## 1. Executive Summary & Purpose

This RFC specifies the technical architecture, SQL dialect translation engine, and synthetic fixture generation for the offline **DuckDB Mock Engine** (`src/bq/mock_engine.py`) and the unified client fallback factory (`src/bq/client.py`).

The primary architectural objective is to satisfy **Invariant 1 (2-Minute Evaluator Rule)** and **Invariant 5 (Dual BigQuery Strategy)**:
1. Evaluators (e.g. Vlad Bondarenko) and CI/CD test runners without GCP billing accounts, service account JSON files, or network access to Google Cloud must be able to clone the repository and run all conversational queries, analytical calculations (Net Revenue, Churn, Margins), self-correction loops, and report generation entirely offline.
2. If `MOCK_BIGQUERY=true` or if Google Cloud Application Default Credentials (`ADC`) cannot be discovered, the system automatically falls back to DuckDB in-memory without throwing unhandled exceptions or crashing the CLI.

### 2.2 GoogleSQL-to-DuckDB Dialect Normalizer

GoogleSQL generated by the LLM (specifically tuned for BigQuery `thelook_ecommerce`) contains dialect-specific constructs that DuckDB does not parse directly. The normalizer `translate_googlesql_to_duckdb(sql: str) -> str` handles:

1. **Table Qualification Stripping:**
   - Strips fully-qualified dataset prefixes:
     - `` `bigquery-public-data.thelook_ecommerce.<table>` `` $\rightarrow$ `<table>`
     - `` `thelook_ecommerce.<table>` `` $\rightarrow$ `<table>`
     - `bigquery-public-data.thelook_ecommerce.<table>` $\rightarrow$ `<table>`
     - `` `<table>` `` $\rightarrow$ `<table>`
2. **Temporal Math Functions:**
   - Translates `TIMESTAMP_SUB(expr, INTERVAL X UNIT)` $\rightarrow$ `(expr - INTERVAL 'X' UNIT)`
   - Translates `TIMESTAMP_ADD(expr, INTERVAL X UNIT)` $\rightarrow$ `(expr + INTERVAL 'X' UNIT)`
   - Translates `DATE_SUB(expr, INTERVAL X UNIT)` $\rightarrow$ `(expr - INTERVAL 'X' UNIT)`
   - Translates `DATE_ADD(expr, INTERVAL X UNIT)` $\rightarrow$ `(expr + INTERVAL 'X' UNIT)`
3. **Date & Timestamp Truncation:**
   - Translates BigQuery bare date parts to string literals:
     - `DATE_TRUNC(col, MONTH)` $\rightarrow$ `DATE_TRUNC('month', col)`
     - `TIMESTAMP_TRUNC(col, DAY)` $\rightarrow$ `DATE_TRUNC('day', col)`
     - `DATE_TRUNC(col, YEAR)` $\rightarrow$ `DATE_TRUNC('year', col)`
4. **Safe Division:**
   - BigQuery `SAFE_DIVIDE(a, b)` returns `NULL` when $b = 0$.
   - Translates `SAFE_DIVIDE(a, b)` $\rightarrow$ `CASE WHEN (b) = 0 THEN NULL ELSE (CAST((a) AS DOUBLE) / (b)) END`.
5. **Double Quoted String Literals in Filter Expressions:**
   - BigQuery accepts double quotes for strings (e.g., `status = "Complete"`).
   - In standard SQL / DuckDB, double quotes denote identifiers.
   - Converts double-quoted literals in expressions where preceded by `=`, `!=`, `<>`, `IN (`, `LIKE` to standard single quotes.

### 2.3 Synthetic E-Commerce Fixtures

The in-memory DuckDB instance (`duckdb.connect(":memory:")`) will be seeded on initialization with realistic, referentially-consistent datasets matching the `thelook_ecommerce` schema:

1. **`users` Table ($\ge 60$ rows):**
   - Columns: `id`, `first_name`, `last_name`, `email`, `age`, `gender`, `state`, `street_address`, `postal_code`, `city`, `country`, `latitude`, `longitude`, `traffic_source`, `created_at`.
   - States: California, New York, Texas, Florida, Washington, Illinois.
   - PII attributes for sanitization testing.
2. **`products` Table ($\ge 50$ rows):**
   - Columns: `id`, `cost`, `category`, `name`, `brand`, `retail_price`, `department`, `sku`, `distribution_center_id`.
   - Brands: Calvin Klein, Tommy Hilfiger, Nike, Levi's, Adidas, Puma, Under Armour.
   - Categories: Jeans, Sweaters, Swim, Tops & Tees, Accessories, Outerwear.
   - Valid cost vs retail price margins.
3. **`orders` Table ($\ge 75$ rows):**
   - Columns: `order_id`, `user_id`, `status`, `gender`, `created_at`, `returned_at`, `shipped_at`, `delivered_at`, `num_of_item`.
   - Spans at least 9 calendar months (e.g. from 2025-01-01 to 2026-03-31) to support trailing 30-day, 90-day, and quarterly aggregation queries.
   - Statuses: Complete (60%), Shipped (15%), Returned (10%), Cancelled (10%), Processing (5%).
4. **`order_items` Table ($\ge 100$ rows):**
   - Columns: `id`, `order_id`, `user_id`, `product_id`, `inventory_item_id`, `status`, `created_at`, `shipped_at`, `delivered_at`, `returned_at`, `sale_price`.
   - Referential integrity linked to valid `orders`, `users`, and `products`.

### 2.4 Unified Client Interface Contract

Both `BigQueryClient` and `MockDuckDBEngine` adhere to the common protocol `DataWarehouseClient`:
- `execute_query(sql: str) -> Any`
- `query_to_dataframe(sql: str) -> pd.DataFrame`
- `query_to_dicts(sql: str) -> list[dict[str, Any]]`
- `is_read_only_query(sql: str) -> bool` enforcement
- `schema_inspector: SchemaInspector`

The factory function `get_bigquery_client(force_mock: bool = False)` encapsulates the fallback logic:
- If `force_mock=True` or `MOCK_BIGQUERY=true` or `google.auth.default()` fails, returns `MockDuckDBEngine`.
- If credentials exist and mock is not forced, returns `BigQueryClient`.
